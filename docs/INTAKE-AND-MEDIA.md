Ordinary issue descriptions no longer require a `Bug:` prefix or a recognized feature name. Known English/Afrikaans failure phrases work without AI. Less obvious wording gets a 2.5-second intent check using the existing model; only a validated, high-confidence report classification enters case creation. The product is still resolved separately or clarified with the customer. Cases are recorded before requesting extra diagnostic details; this does not confirm a software bug.

New IDs use PS (PlaySmart), RS (ReadSmart), SA (Skoolio Admin), or GS (general/unknown). A single atomic numeric sequence continues across products. Existing IDs are never renamed, including when an owner corrects a product. Lists, case references, history, notifications, imports and recovery recognize every prefix. Product aliases include PS, RS and rsmart.

Voice notes and screenshots are acknowledged and durably queued before any provider calls. A background alarm downloads authenticated Twilio media and extracts text outside the request mutex. Case changes, the reply outbox and job completion commit together. Duplicate webhook delivery reuses the recorded acknowledgement/result. Interrupted extraction has a bounded lease and attempt limit; failed reading produces a truthful request to resend or describe the issue in text.

Supported images: JPEG, PNG and WebP. Supported audio: OGG (including WhatsApp Opus), MP3, M4A/MP4, WAV and WebM. Limit: three files per message, 5 MiB each. PDFs and videos are not supported. Media must belong to the signed message and configured Twilio account. Only the authenticated Twilio API and its HTTPS media CDN redirect are allowed; account credentials are never forwarded to the CDN.

Audio uses `whisper-1`; screenshots use the existing vision-capable `OPENAI_MODEL`. Raw attachments are sent to OpenAI for extraction and are not stored in the Worker or shown as image/audio previews in the dashboard. Sanitized transcripts and screenshot descriptions become case text. Temporary media URLs are removed after extraction. Twilio retains its original media under its own configuration. Extraction is fallible and cannot prove the cause of a problem.

API formats checked against [OpenAI structured outputs](https://developers.openai.com/api/docs/guides/structured-outputs), [transcription](https://developers.openai.com/api/reference/cli/resources/audio/subresources/transcriptions/methods/create), [vision](https://developers.openai.com/api/docs/guides/images-vision), and [Twilio media](https://www.twilio.com/docs/messaging/api/media-resource).

Validation: unit tests cover ordinary language, semantic classification, prefixes, owner history/editing, asynchronous extraction, deduplication, redaction and unsafe URLs. `npm run test:media:runtime` exercises bundled workerd, real alarms, multipart OGG upload, screenshot follow-up, case mirrors and outbound replies using provider fixtures. Real WhatsApp media/provider compatibility still needs an owner-sent voice note and screenshot after deployment.
